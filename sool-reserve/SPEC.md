# SOOL RESERVE — 개발 명세서 v2 (검증·개선판)

> 원본 프롬프트(v1)를 검증해 **모순 제거 · 법적 리스크 보강 · 1~2단계 범위 확정 · 데이터/수익 로직 명확화**를 반영한 버전입니다.
> 법령 관련 항목은 개발 설계 기준일 뿐 법률 자문이 아닙니다. `[확인 필요]` 표시는 운영 전 세무사·변호사·국세청/관할 세무서 확인 대상입니다.

## 0. 핵심 요약

| 구분 | 결론 |
|---|---|
| 원본 평가 | 방향·브랜드·수익 관리 개념은 우수. 단, **치명 2건 / 높음 4건 / 중간 6건** 보완 필요 |
| 가장 큰 리스크 | ① "주종 = 온라인 판매 가능"으로 오인될 구조 ② 실존 양조장·상품을 데모로 쓸 때의 오인·상표 문제 |
| 가장 큰 모순 | "가격은 판매 승인 후 표시" ↔ "가격대별 컬렉션 노출" — 승인 전엔 컬렉션이 비게 됨 |
| 해결 핵심 | **사이트 운영 모드 3단계(SHOWCASE → PRIVATE_TEST → LIVE)** 를 단일 설정으로 두고, 모든 구매·가격·결제 노출을 이 플래그 하나로 제어 |
| 1~2단계 산출물 | 고객 브랜드 사이트(7개 핵심 페이지) + 관리자(9개 핵심 메뉴) + 수익 계산 엔진 + 데모 데이터(가상) |

## 2. 운영 모드 (모든 판매 기능의 단일 스위치)

| 모드 | 대상 | 가격 | 장바구니/주문/결제 | 성인 인증 | 비고 |
|---|---|---|---|---|---|
| `SHOWCASE` (기본) | 일반 공개 | 관리자 토글 시 "참고가"로만 | **UI·API 모두 차단** | 고지 모달만 | 1~2단계 상태 |
| `PRIVATE_TEST` | 개발자·관리자 계정만 | 표시 | 작동(Mock PG, 실결제 없음) | Mock 인증 | 3단계 개발용 |
| `LIVE` | 일반 공개 | 표시 | 작동 | 실 인증 필수 | 아래 **활성화 조건 전부 충족** 시에만 전환 가능 |

**LIVE 전환 조건 (시스템에서 체크, 하나라도 미충족 시 버튼 비활성)**
- [ ] 판매 활성 판매자 ≥ 1곳, 해당 판매자 서류(제조면허·통신판매업 신고·전통주 적격 근거) 승인 완료
- [ ] 판매 대상 상품의 통신판매 적격 상태 = `VERIFIED`
- [ ] 성인 인증 공급자 실키 등록 및 테스트 통과
- [ ] PG 실키 등록 + 판매자별 정산 구조 확인 체크
- [ ] 법적 고지(이용약관·개인정보처리방침·판매자 정보·경고문구) 게시 완료

상품 단위 판매 가능 여부 = `운영 모드 == LIVE` AND `판매자 판매 활성` AND `상품 적격 VERIFIED` AND `재고 > 0` AND `상품 상태 == PUBLISHED`

## 4. 브랜드·디자인 (원본 유지 + 보강)

- 브랜드: **SOOL RESERVE / 술의 격** — 슬로건 "술에도 격이 있습니다." / 서브 "시간과 장인정신이 빚어낸 대한민국의 가장 귀한 술."
- 컬러 토큰: `ivory #F7F4EE` · `charcoal #202020` · `gold #B69A68`(포인트 전용, 면적 5% 이하) · `burgundy #4C202B` · `beige #ECE5D8`(상품 배경)
- 폰트: 영문 세리프 `Cormorant Garamond`, 한글 본문 `Pretendard`, 한글 제목 `Noto Serif KR`
- 레이아웃: 최대폭 1440px, 섹션 간 여백 120px(PC)/72px(모바일), 상품 그리드 PC 4열/태블릿 3열/모바일 2열
- 모션: 스크롤 페이드업 600ms, `prefers-reduced-motion` 시 비활성
- **이미지 정책 (보강)**: 실제 상품 사진이 없으면 **브랜드 톤 SVG 병 일러스트**(주종별 실루엣)로 대체. 실존 상품을 연상시키는 생성 이미지 금지. 이미지에 `출처/저작권` 필드
- 금지: 할인율 배지, 카운트다운, "최저가" 문구, 음주 장면 연출
- 접근성: 대비 4.5:1 이상(골드 텍스트는 어두운 배경에서만), 모든 이미지 alt

메인 8개 섹션·카피는 원본 그대로 사용 (HERO / THE COLLECTION / PRICE COLLECTION / MASTER BREWERIES / PREMIUM GIFT / LIMITED EDITION / TASTE DISCOVERY / BRAND PHILOSOPHY).

## 6. 수익 계산 규칙 (단일 소스)

**입력 (상품별, 원 단위 정수)**
- `P` 판매가(VAT 포함) / `basis` 수수료 기준: `판매가 VAT 포함`(기본) 또는 `VAT 제외`(P ÷ 1.1, 원 미만 버림)
- `r` 수수료율(%) — 상품값 없으면 양조장 기본값 → 시스템 기본값 순
- `pg` 결제비율(%) + 부담 주체(플랫폼/판매자)
- `ship` 플랫폼 부담 포장·배송비 / `promo` 플랫폼 부담 할인 / `etc` 기타 변동비

**계산**
```
기준금액        B  = basis == VAT제외 ? floor(P / 1.1) : P
수수료 수익     C  = round(B × r / 100)
플랫폼 결제비   F  = 부담주체 == 플랫폼 ? round(P × pg / 100) : 0
공헌이익        M  = C − F − ship − promo − etc
수수료 대비 이익률 = M ÷ C × 100   (C = 0 이면 표시 "–")
거래액 대비 이익률 = M ÷ P × 100   (추가 지표: 상품 간 비교용)
판매자 정산 예상액 = P − C − (부담주체 == 판매자 ? round(P × pg / 100) : 0)
```
- 반올림: 원 단위 사사오입, 비율은 소수 1자리
- 대시보드·상품 목록·선별 필터 모두 **같은 함수** 사용 (`lib/economics.ts`) + 단위 테스트 필수
- 매입형(WHOLESALE)은 MVP 비활성: `M = P(VAT제외) − 매입가(VAT제외) − 비용` 공식만 정의
- 고객 화면 API 응답에서 수익 필드 **직렬화 단계에서 제외** (프론트 숨김만으로 처리 금지)

**상품 선별 필터 예시 (관리자 저장 가능)**
판매가 ≥ 100,000 · 공헌이익 ≥ 20,000 · 선물 적합성 ≥ 4 · 양조장 입점 승인 · 재고 ≥ 1 · 적격 VERIFIED
→ 결과에서 바로 "추천 슬롯에 추가" 가능. 점수 null인 상품은 "미평가"로 분리 표시(0점 취급 금지)
